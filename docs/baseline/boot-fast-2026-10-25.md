## Subsequent evidence and status-stack correction

Joel explicitly approved the prepared recovery. Its first preflight stopped
before upload because the ordinary 22:00 night transition entered `page_natt`.
For controlled testing, the exact saved night-start time (22:00:00) was recorded,
acknowledged temporarily as 23:59:00 and the normal night-exit action was used.
The one claimed OTA attempt in `.panel-ci/run-20261025-220421-465126/` then
panicked and rolled back too. Its plan's ledger remains failed and is not reused.
The night-start time was acknowledged back to 22:00:00 after that failure.

The second retained crash is an Abort. Symbolizing return *call sites* (RISC-V
return address minus two, rather than the next instruction/function) against
its exact frozen ELF identifies `vApplicationStackOverflowHook`, `port.c:682`,
under `esp_system_abort` and `panic_abort`. The unadjusted return address had
misleadingly pointed at the adjacent `vPortCoprocUsedInISR` function. The old
firmware's foreign-build crash record does not retain the task name.

The HTTP server runs on core 0 with an 8192-byte stack. Its deferred status
formatter nests the generated application formatter. A GCC 14.2.0 RISC-V
`-fstack-usage` compile with the actual target flags measured these frames:

| Formatter | Before | After | Reduction |
| --- | ---: | ---: | ---: |
| HTTP status wrapper | 3408 B | 608 B | 82% |
| Application/boot status | 1760 B | 320 B | 82% |
| Nested pair | 5168 B | 928 B | 82% |

The former pair alone consumed 5.0 KiB of the 8 KiB stack, before nested timing,
JSON, numeric conversion, allocation and HTTP calls. Its single `operator+`
expressions kept dozens of temporary strings alive while invoking nested
formatters. Each field now appends in separate full expressions; temporary
lifetimes end before the next field or nested callback. Both interfaces retain
all existing JSON values, quoting and types. No stack-size increase is used.

The HTTP worker also samples its own real minimum-free stack bytes **after**
formatting and reports `status_worker_stack_min_free_bytes`. IDF's task header
explicitly specifies bytes, unlike upstream FreeRTOS's words. The scan and its
formatting remain on the HTTP worker. The measured worker time includes the
status formatter and watermark scan, before observer-field append and sending.
These operations perform no C6 RPC and never execute on LVGL. Static frame totals do not establish the
complete task's dynamic peak; physical verification and the real watermark are
still required. Native ASan/UBSan tests compile both actual formatter bodies,
compare complete JSON contracts (including no extra fragment, escaping, large
counters and booleans), and enforce a modest local-frame budget.

Raw target `.su` files, compile logs and both return-address decoding attempts
are retained in `.panel-ci/boot-fast-20261025/`. A new source-bound recovery plan
is required for this correction; the original two failed attempts are never
rewritten or counted as passes. Joel separately authorized continuing with a
new correction: “men jag godkänner sen ny asså ba kör på”.

Inspection of the installed framework identifies another bounded factor:

has no high-frequency-loop request and drains one proven 8 KiB chunk per

on background success, three failures or the five-second wait timeout.
No larger read, permanent fast loop or steady-state CPU/power change is added.
`boot_loop_restored_ms` and fresh `loop_interval_ms` report the restoration.
