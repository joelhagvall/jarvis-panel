# Physical screen capture and remote touch, 2026-10-24

Installed on the Waveshare ESP32-P4 7B through the checked firmware workflow. The
authenticated interface is documented in [remote-panel.md](../remote-panel.md). No Jarvis
or HA integration change/restart was needed. No paid voice/model call was used.

## Implementation

- The actual last-submitted 1024×600 RGB565 hardware framebuffer is copied on the main task
  after frame-completion acknowledgement. LVGL rendering cannot run concurrently with the
  copy. This preserves the existing asynchronous double buffering and captures top/system
  layers as well as the active page.
- JPEG quality 90 / YUV444 encoding runs on the HTTP task using the P4's hardware encoder.
  A separate raw route returns the exact RGB565 frame; the CLI converts it to lossless PNG.
  Buffers are allocated per request and freed after transfer. No video stream runs in idle.
- An event-driven virtual LVGL pointer performs actual hit testing, click/drag/release and
  swipe callbacks. Physical touch takes priority. Main-task jobs use shared ownership so
  HTTP timeout cannot free an in-flight buffer or gesture job.
- Every route requires a separate random credential. It is kept in the ignored private
  secrets file. The CLI refuses redirects and bypasses proxy environment variables. Form
  sizes, coordinates, fields, duplicates and durations are bounded. No firewall/router
  configuration was changed.
- The Mac's generic mDNS lookup took 5,009 ms waiting for a missing AAAA record. IPv4-only
  resolution took 6.5 ms. The CLI uses IPv4 for `.local` HTTP devices and keeps the Host header.

## Verification

238 free local tests and ESPHome validation passed. Native C++ protocol checks used ASan and
UBSan, checked every changed token byte, boundary/malformed gestures and 50,000 random inputs.
Host tests cover raw colour order, truncated images, private image files, redirect refusal,
ambiguous labels, bounds, IPv4 resolution and the rule against retrying an input request.

The explicit live [physical smoke test](../../tools/panel_ui_test.py) also passed:

1. Unauthenticated status and touch returned 401; an out-of-range touch returned 400.
2. A real Hemmet tab click changed the page and produced the correct physical screenshot.
3. The settings gear opened the real overlay. An exact PNG included both overlay and page.
4. A real drag changed screen brightness from 23 to 30%, then restored exactly 23%.
5. Tavla opened by its tab. A real right swipe returned to Hemmet.
6. Eight captures completed; idle free PSRAM was exactly 19,352,352 bytes before and after.
7. The original dashboard page was restored. HA independently reported brightness 59/255
   (23%) and playback idle at volume 0.2.

Two JPEGs from separate orb windows had presented-frame IDs 455 and 510. The orb-region
mean absolute RGB differences were 6.01, 6.85 and 8.21, confirming new animation pixels.
The captured orb was visually inspected, with the current painting and frameless listening
text visible. The first attempt tried to fit two captures into one two-second window and
missed the second; the successful comparison used one capture in each of two windows.

| Minimum free internal RAM | 317 KiB | 307 KiB |
| Lowest PSRAM since boot, including earlier captures | 17,925 KiB | 16,409 KiB |

The short page test shows comparable idle rendering and about 19.35 MB free PSRAM. The
lowest reading includes earlier transient capture/encoder allocations. After 16 captures,
the final status still showed 19,352,352 bytes free PSRAM and 314,116 bytes free internal
RAM at 674 seconds uptime. No new errors or crashes appeared in the captured runtime log.

Frame copying took 24–26 ms on the main task. JPEG encoding/network transfer happens
afterward on the HTTP task, so capturing is an explicit debug operation with real cost.
Individual JPEG transfers measured 147–445 ms; the two orb captures took 257 and 351 ms.
Back-to-back captures can take about a second because the CLI waits/retries the two-per-second
rate limit. The exact 1,228,800-byte transfer took about 1.9–2.2 seconds. Normal UI use does
not request images. These are short tests, not a long soak or optical latency measurement.

The baseline comparator still flags intentional firmware growth and the compressed atlas's
previously documented higher CPU render time versus older raw-animation builds. The new
interface adds 52,880 firmware bytes and 308 static RAM bytes over the immediate previous
build; its HTTP task and connection state also consume roughly 10 KiB internal RAM. It did
not produce a material rendering change in this short comparison.

Screenshots observe firmware pixels; they cannot establish physical LCD flicker, real
backlight output, speaker sound or touch-to-photon latency. Those still require observation.

## Settings readability follow-up

The settings sheet now uses `bg_opa: COVER` instead of `96%`. Exact framebuffer captures
showed underlying page text through the old sheet. The fully opaque sheet removes that
interference while retaining the rounded outline and the surrounding 55% black scrim.
No blur, image asset or extra framebuffer was added.

245 free tests and ESPHome configuration validation passed before installation. The physical
UI smoke test passed, including settings capture, tabs, swipe navigation and capture-buffer
release. Exact PNGs on both the dashboard and Hemmet showed a uniform sheet background;
the same empty 20 × 25 pixel patch matched across both pages. Brightness remained 23%,
night brightness 12% and volume 20%. The dashboard was restored after testing.

Flash remains 2,711,364 bytes and static RAM 145,310 bytes. The three-pass idle page test
measured orb redraws of 24.0–24.8/s and average rendering of 17.3–17.4 ms, versus
24.0–24.5/s and 17.6–17.7 ms immediately before. Free PSRAM remained about 19.35 MB;
internal memory was 306 KiB during the test versus 307 KiB before. This short comparison
does not show a material rendering or memory regression. The boot recorded zero crashes,
with setup at 4.94 s and the painting at 12.42 s, versus 4.96 s and 12.08 s before.
